# Retrieval Tuning Results — 2026-10-03

Golden-set evaluation of context size (`top_k`) and reranker candidate pool
(`RERANK_POOL_MULT`) on a single-paper golden query set. The golden set, raw
answers and per-run reports are kept local (development artifacts); this file
records the method, the numbers and the decision.

## Setup

| Item | Value |
|---|---|
| Golden paper | `2026086448` — *Uncertainty-Aware Reinforcement Learning System with Blended Surrogate Models for Electromagnetic Structure Optimization* (30 chunks) |
| Queries | 26 scored (23 English, 2 Hindi, 1 Telugu) across factual, numeric, methodology, setup, table, results, synthesis, paraphrase and multilingual categories; 6 abstention (unanswerable / false-premise) queries scored by hand |
| Corpus | 2,894 chunks, `scientific_papers` collection |
| Embeddings / reranker | `BAAI/bge-m3` (int8 ONNX, CPU) / `BAAI/bge-reranker-v2-m3` (CPU) |
| Answer model | `nvidia/nemotron-3-ultra-550b-a55b` via NVIDIA NIM, **failover disabled** so every answer comes from one model |
| Hardware | 4-core CPU, no GPU |
| Harness | `docs/Eval/run_live.py --with-answers` then `docs/Eval/evaluate.py --k 5` |

All runs are scored at `k=5` so Precision/Recall are comparable across `top_k`
settings (P@k falls with k by definition, independent of quality).

**Key facts** = answers that state every required fact for the query (e.g. all
of `28.12 GHz`, `-52.2 dB`, `8.93%`), checked after Unicode normalization.

substrate question (Rogers RO4003C) was corrected to FR-4.

## Findings

1. **Retrieval plateaus at top_k = 8.** Paper-level recall is 1.0 and MRR /
   nDCG vary by < 0.03 from k8 onward — within noise for 26 queries.
2. **Answer completeness scales with context, not retrieval.** Key facts rise
   from 17/26 (k5, k8) to 19–20/26 (k16, or any ×3 pool).
3. **The Jaccard grounding judge is not reliable across these settings.** It
   drops on both ×3 runs (0.309, 0.404) even though they answer more facts,
   because synthesized or paraphrased claims share fewer tokens with their
   source chunk. The cross-encoder judge scores every claim grounded (1.000) in
   every run, so it does not discriminate either. Neither grounding score should
   drive this decision; key facts and latency do.
4. **A wider reranker pool works mechanically but rarely pays.** At k8 the
   "model disagreement" chunk entered the pool (BM25 rank 11, dense rank 39) but
   the cross-encoder scored it 14th (0.193), behind introduction chunks that echo
   the query wording. ×3 costs ~2.5× retrieval time on CPU for +1 key fact.
5. **Multilingual numbers are too small to act on** (2 Hindi, 1 Telugu queries).
6. **Remaining misses are not a context-size problem:**
   - G06 — the target paper is not ranked first for a generic question.
   - G21 — the workflow chunk does not name SAC.
   - G23 — the answer chunk is mostly a broken equation plus figure labels from
     PDF extraction; it is not retrieved at any setting. Fix is chunk quality.
   - G04 / G17 — answers drop a precise figure (72%, 80.3%) the context contains.

## Decision

- **Development setting: `MAX_CONTEXT_CHUNKS=16`, `RERANK_POOL_MULT=1`** (local
  `.env`). Best Jaccard overall (0.621) and 19/26 key facts at 9.0 s retrieval.
- **Code defaults unchanged:** `MAX_CONTEXT_CHUNKS` stays 12 and
  `RERANK_POOL_MULT` defaults to 1. Both are now environment-overridable.
- `RERANK_POOL_MULT=3` is worth revisiting on GPU hosts, where reranking 40
  pairs is cheap.

## Follow-ups

- Clean figure/equation residue out of chunks (G23 class).
- Expand the golden set beyond one paper and to ≥10 Hindi/Telugu queries before
  drawing multilingual conclusions.
- Replace or calibrate the grounding judge so it separates configurations.
